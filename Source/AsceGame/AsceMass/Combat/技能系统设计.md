# 技能与动作系统设计（Asce RTS）

> 状态：**设计定稿**（待实现；已按"技能客户端预测表现 / CastConfig(InstancedStruct) / Bone 模式动画"修订）
> 相关：`建筑系统设计.md`、`Ether系统设计.md`、`Vision/视野与迷雾系统架构设计.md`、`Networking/*`（复制能力）、`UI/UI.md`
> 说明：攻击（自动）与技能（主动）**共用同一套动作状态机与动画/复制管线**，所以攻击规则也写在本文件里。

## 1. 目标与边界

- **主动技能**：玩家操作释放，共 **3 个槽位**（1/2/3 ↔ Q/W/E）。
- **被动技能**：v1 **只做常驻属性加成**（在 def 层改属性），不做事件触发。
- **释放前必须停下**：收到技能指令的单位**无条件先停止移动**——即使该单位这个技能放不出来（射程不够/没蓝/CD/槽位为空）也要停，
  否则"框选一堆移动中的单位放技能，有的放有的还在走"非常诡异；同时"停下"也是给玩家的**指令回执**（否则玩家分不清是没点到还是放不出来）。
- **服务器权威**：目标解析、射程/可见性校验、CD、蓝耗、结算、生成物**全部在服务器**。
- **客户端预测表现（手感）**：客户端用本地数据（技能表/槽位CD/蓝/射程/可见）做校验，通过则**立即播放表现层动画**并同时把指令发给服务器；
  服务器接受 ⇒ 动作态通道的边沿复制到达即为**隐式确认**（客户端继续播）；拒绝 ⇒ 逐单位回执（带原因），客户端**取消动画**。
  **结算永远在服务器**，客户端只预测表现。
- **各算各的、到点硬切**：服务器时间线（前摇/Trigger/持续）与客户端动画时长**各自独立**、不做拉伸对齐；客户端按复制的状态边沿硬切动画。
- **生成物也是 Mass entity**：创建必须**排队 → 下一帧的生成阶段**（项目不变式：实体创建/销毁必须在模拟阶段 2 之前）。
- **不移动施法 / 不追击**：射程不够就直接不释放，不走过去。

## 2. 数据模型

### 2.1 技能定义（静态，数据表）

```cpp
FAsceActionDef   // 技能/动作元数据（共享表，两端都注册）
{
    int32  Id;
    uint8  Type;              // Active / Passive（被动 v1 只做属性加成）
    uint8  TargetKind;        // None / Point(非指向) / Unit(指向)
    uint8  TargetRelation;    // ★新增：Enemy / Friendly / Self / Any（目标关系校验）
    uint8  Delivery;          // Instant(直接生效) / Projectile(弹道) / SpawnAtTarget(在目标位置生成)
    float  Range;             // 施法距离（cm）
    uint8  RangeKind;         // 距离口径（与攻击同一套：近战=表面；远程=低→高表面、高→低圆心）
    float  Cooldown;          // 冷却（秒）
    float  ManaCost;
    int32  ProjectileDefId;   // 弹道实体定义（与 ProjectileDefRow 二选一，暂留）
    int32  SpawnGroupId;      // 生成物组定义
    FInstancedStruct CastConfig;            // ★动作管线配置（多态，见下）：时间 + 施法/持续动画的**唯一来源**
};

// ★动作管线配置（FInstancedStruct）——服务器只取时间，客户端只取动画资产
FAsceSkillCastConfig（基类：提供虚函数 GetCastAnim/GetChannelAnim/GetTriggerTime/IsChannel 等，返回 TSoftObjectPtr<UAnimSequence>）
 ├─ FAsceNormalCastConfig  { TSoftObjectPtr<UAnimSequence> CastAnim; float TotalCastTime; float TriggerTime; }
 │      // TotalCastTime = 动作总时长（动画尾巴）；TriggerTime = 真正结算时刻（可 < TotalCastTime：
 │      // 动画播到某个位置就触发；**两个时间各算各的，到点硬切**）
 └─ FAsceChannelCastConfig { TSoftObjectPtr<UAnimSequence> CastAnim; float CastTime; TSoftObjectPtr<UAnimSequence> ChannelAnim; float ChannelDuration; float TickInterval; }
        // 前摇 CastTime → 前摇结束=真正释放 → 进入 Channel：循环 ChannelAnim + 每 TickInterval 结算 → ChannelDuration 结束
```

- **时间字段全部迁进 `CastConfig`（单一事实源）**：def 不再有 `CastTime / ChannelDuration / ChannelTickInterval`；
  `EAsceCastKind` 退役（由 CastConfig 的实际类型区分；**Instant 折叠成 NormalCast + `TotalCastTime=0 / TriggerTime=0`**——v1 只有"普通/持续"两种）。
- **攻击也走同一套模型**：攻击不入动作表；配置放**单位 def**（`AttackCastConfig`，`FAsceNormalCastConfig`），时间按 1.0x 配置、
  `AttackSpeed` 作为缩放系数（作用于动作时长/Trigger/播放速度）。`FAsceCombatFragment.BaseAttackTime` 迁移为派生/兼容字段。
- 动画**直接引用资产**（`TSoftObjectPtr<UAnimSequence>`）：烘焙帧段由单位类型的 AnimSet 按资产引用解析（§7.2）。**动画统一跟 CastConfig 走**：
  攻击读 `AttackCastConfig.CastAnim`、技能读各自 `CastConfig` 的 `GetCastAnim()/GetChannelAnim()`；没有独立的状态→动画表（不再有保留 clip 名/回退链）。

### 2.2 实体：技能槽位（真实数据，且要复制到客户端）

```cpp
USTRUCT() struct FAsceSkillSlot
{
    int32  SkillId = 0;              // 0 = 空槽
    double NextReadyServerTime = 0;  // 下次可释放的**服务器世界时间**（CD）
};

USTRUCT() struct FAsceSkillSlotsFragment : public FMassFragment
{
    FAsceSkillSlot Slots[3];
};
```

- **槽位是真实数据不是 UI**：指令里只带槽位号，服务器按"该单位这个槽位是什么技能"解析（因此一条指令就能让多单位同时放不同技能）。
- **技能状态（CD 等）存在槽位里** ⇒ 玩家交换槽位时，技能**连同它的 CD** 一起换位（不重置）；蓝耗/等级等运行时数据同理。
- 为"**单位自定义技能**"（每单位不同槽位内容）预留了空间。
- 配置指令：`SetSkillSlot(SelectedNetIDs, SlotId, SkillId)`；**槽位即"拥有"**（没有独立的技能拥有清单）——
  服务器只校验技能在动作表里存在且为主动技能 + `NotOwned`，然后写入/交换槽位。

### 2.3 实体：动作/战斗运行时（服务器专有，不复制）

```cpp
USTRUCT() struct FAsceCombatFragment : public FMassFragment   // 挂载 = 该实体能主动攻击；不挂 = 只能被打
{
    // 静态（来自 def）
    float AttackRange; float AttackDamage;
    float BaseAttackTime;    // 攻击动作自然时长
    float AttackSpeed;       // PlayRate = AttackSpeed / 200 + 0.1（180 → 1.0x）
    uint8 RangeKind; uint8 bAutoAttack : 1; uint8 bProjectile : 1;
    int32 ProjectileDefId;

    // 运行时
    FMassEntityHandle DesignatedTarget;  // 指定目标（持久，失效即清）
    float  NextScanTime;                 // 0.3s 节流扫描
};

USTRUCT() struct FAsceActionFragment : public FMassFragment      // 当前动作（唯一真相）
{
    uint8  ActionState;        // Idle/Move/Attack/Casting/Channel/Dying
    int32  ActionDefId;        // 攻击=内置 id；技能=SkillId
    double TriggerTime;        // ★真正结算时刻（普通=TriggerTime；持续=前摇结束进Channel那一刻）
    double ActionEndTime;      // 动作结束（普通=动作总时长；Channel=持续结束）
    double NextReadyTime;      // 本动作的 CD 结束（攻击专用；技能记在槽位上）
    FMassEntityHandle ActionTarget;
    float  FacingYaw;          // 本次动作朝向（动作开始时定死）
    double NextTickTime;       // Channel 的周期结算
    uint32 Counter;            // 递增序号（每次"下发一次动作"++，供客户端播一次）
};
```

## 3. 指令流

> **没有手动攻击指令**：攻击由自动攻击承接（见 §2 状态机），玩家只有 移动 / 技能 / 停止 三类指令。
> 历史遗留的 `IssueAttackOrder` / `ServerRequestAttackOrder` / `FAsceAttackOrderFragment` 已移除，不要再加回来。

### 3.1 技能释放指令

```cpp
FSkillOrder { uint8 SlotId; FVector2D TargetPos; FMassNetworkID TargetNetID /*可无效*/; TArray<FMassNetworkID> SelectedNetIDs; }
```

- 客户端**只发槽位号**，不解析技能；目标类型由服务器按槽位里的技能 def 决定。
- 客户端**统一带上** `TargetPos` 与 `TargetNetID`（后者可能无效）：非指向技能用 Pos，指向技能用 NetID。
- **指向技能的交互（已定）**：按键进入**目标选择模式**（高亮可选目标/范围指示），**左键确认**释放；右键/再按一次取消。
  非指向技能不进模式，直接落鼠标地面点。
- **客户端预测（只预测表现，不预测结算）**：
  1. 本地用已复制的数据校验：槽位非空 / 技能在本地动作表 / CD 到 / 蓝够 / 目标合法且可见 / 在射程内；
  2. 通过 ⇒ **立即播前摇动画 + 面向目标**，同时发 RPC；不通过 ⇒ **不播动画**。
     注意：**指令始终照发**（本地 CD/可见数据有延迟，本地拦掉会丢指令；服务器才是权威），本地校验只决定"要不要预测动画"；
  3. 对账（硬规则）：
     - **权威动作态永远最高优先**：服务器接受后会写 `FAsceActionFragment`，动作态通道的**边沿复制到达 = 隐式确认**；
     - 权威态与预测一致（同单位/ActionDefId、Counter 前进）⇒ 继续播（"各算各的"：不做时间轴对齐，状态切换硬切）；
     - **不一致**（服务器没接受/被别的动作占用）⇒ **立即取消动画**；
     - **超时取消**：N×RTT 内没等到匹配的权威态 ⇒ 取消（防幽灵动画）；
     - 显式**拒绝回执**（逐单位、带原因）只用于快速取消与原因反馈。
- 服务器逐单位处理：
  1. **无条件停止移动**（清移动命令、速度清零）；
  2. 校验：槽位非空？CD 到？蓝够？目标合法（TargetKind + **TargetRelation**；指向目标**必须可见**；**在射程内**——距离口径按 RangeKind）？当前动作是否允许被技能打断（**技能优先级最高，可打断攻击**）？
  3. 通过 ⇒ 进入动作：**设朝向面向目标**，按 `CastConfig` 进入 `Casting`（持续施法的前摇也是 `Casting`）；
     **cost / CD / effect 在 Trigger 那一刻处理**（见 §5）——**进入动作时不扣蓝、不写 CD**；
  4. 不通过 ⇒ 单位停在原地（保持 Idle / 自动攻击照常）+ 逐单位拒绝回执。

### 3.2 停止指令（S）

- `S` = 向当前选中单位发送**停止指令**：停止移动 + 取消正在进行的施法（含持续施法，**已生效的周期效果保留**）→ 回到 `Idle`。
  `S` 同时**立即取消客户端的预测动画**（不等服务器回执）。
- **不影响自动攻击**：攻击只受"是否开启自动攻击"这个开关调控（停止指令不关它）。
- 这是**唯一**的主动取消手段（见 §4 打断矩阵）。

## 4. 动作状态机与打断矩阵

状态：`Idle / Move / Attack / Casting / Channel / Dying`。同一时刻**只有一个动作**。

| 当前 \ 事件 | 移动指令 | 技能指令 | 停止(S) | 死亡 |
|---|---|---|---|---|
| **Attack** | 打断（不结算） | 打断 → 施法 | 打断 | 打断 |
| **Casting** | **不打断** | **打断**：新技能可释放 → 顶掉当前施法（不结算）改放新技能；不可释放 → 维持原施法 | 取消 | 打断 |
| **Channel** | **不打断** | **打断**：同上（已生效的周期效果保留；未结算的丢弃） | 取消（保留已生效） | 打断 |
| **Move** | 替换 | 停止移动 → 施法 | 停止 | 打断 |
| **Idle** | 进入 Move | 施法 | —（保持 Idle，自动攻击照常） | 打断 |

- **施法不能被移动打断**（规则已定），但可以被 `S`、**新的技能指令**（见下）、死亡终止。
- 施法期间单位**静止**；动作结束回到 `Idle`（持续施法在前摇结束后进入 `Channel`）。
- **结算点在 Trigger**（普通施法 = `TriggerTime`，可早于动作总时长；持续施法 = 前摇结束）：
  - Trigger **之前**被打断/取消 ⇒ **不结算、不付费**（蓝/CD 未落）；
  - Trigger **之后**被打断（动画尾巴 / Channel 期间）⇒ **已结算、已付费且不返还**（Channel 已生效的周期效果保留）。
- **施法前摇期间目标死亡不取消施法**：照常走到 Trigger 那一帧，发现目标不存在 ⇒ 什么都不做（见 §5）。
- **施法中收到新的技能指令**（手感优先）：先对新技能做**完整校验**——能放就**直接顶掉**当前施法并改放新技能（不需要玩家先按 `S`）；放不了就**维持原状态**（继续原施法）。
  被顶掉/取消时按上面的"Trigger 前/后"费用规则处理。
- "**无条件停止移动**"是对"正在移动的单位"的公共动作（施法者本来就静止）；上面的"维持原状态"只针对"施法动作是否被顶掉"。

## 5. 结算

- **普通施法（NormalCast）**：`Casting` 开始 → 播前摇动画（`CastAnim`）；**`TriggerTime` 那一刻结算**：
  先处理 cost 与 CD（扣蓝、写 `Slots[i].NextReadyServerTime = now + Cooldown`），再结算 effect（生成弹道 / 在目标位置生成 / 直接生效）。
  结算时**只需再查一次"目标是否还存在"**：存在 → 生效；不存在 → **什么都不做**（不生成、不补刀）。
  结算后动作继续播到 `ActionEndTime`（动画尾巴）→ `Idle`。
  若 Trigger 时蓝已不够 → **释放失败**：不扣、不落 CD、不生成，回 `Idle`。
- **持续施法（Channel）**：`Casting` 前摇（`CastTime`）→ **前摇结束那一刻是"真正释放"**：扣蓝 + 落 CD + 首次结算，进入 `Channel`；
  然后循环播 `ChannelAnim`、每 `TickInterval` 结算一次，直到 `ChannelDuration` 结束 / 被取消 / 死亡；**被打断保留已生效效果、蓝/CD 不返还**。
- **弹道**：
  - 生成位置 = 施法者**前方**（`pos + forward * SpawnOffset`）；
  - 指向性（Unit）：**追踪目标直到命中**（命中用**距离阈值**，不做物理碰撞）；**目标中途死亡 → 弹道直接消失**；
  - 非指向性（Point）：直线飞向目标点。
- **生成物排队**：结算当帧只入队，**下一帧生成阶段**创建实体（弹道/召唤/地面效果）。
- **迷雾**：不对雾内目标施法（客户端本来就没有视野外单位的 NetID ⇒ 天然防隔雾狙击）；服务器再做一次可见性兜底。

## 6. 复制通道

### 6.1 动作态通道（驱动动画；详见战斗同步讨论）

```cpp
// 基类 = 被动通道专用（TemplateID 不复制）；见 `Networking/Mass复制设计.md`
USTRUCT() struct FAsceActionReplicatedAgent : public FAsceLightReplicatedAgentBase
{
    // 单位类型**不在 payload 里**：模板常量，客户端 spawn 时由 `FAsceUnitDefFragment.UniqueTypeId` 自带
    uint8 ActionState;    // Idle/Move/Attack/Casting/Channel/Dying（**全部由服务器发**）
    uint8 ActionDefId;    // 攻击=内置 id；技能=SkillId（客户端据此查动画段/时长）
    uint8 Counter;        // 递增：变了 → 客户端"播一次"
    uint8 PlayRateQ;      // 播放速度量化（0.1~2.0）
    uint8 FacingQ;        // 本次动作朝向（0..255 → 360°）
};
```

> 复制通道的**单项开销 / 单帧 64KB 上限 / owner 与被动 bubble 分工 / 轻量 agent（TemplateID 不复制）**
> 见 `AsceMass/Networking/Mass复制设计.md`。

- **`Idle/Move` 也由服务器发**（不让客户端从速度推断）：状态与朝向在**同一个 USTRUCT**里一次到达，不依赖跨通道顺序
  （否则会出现"服务器已停+攻击，但速度/位置通道还慢一帧，客户端以为自己在 Move"）。
- 客户端规则：`ActionCounter` 变 → 播一次；回 `Idle` → **硬切**；`Dying` → 播死亡；`Move/Idle` 循环。
- 朝向：`Attack/Casting/Channel` 用 `FacingQ`；`Move` 用本地速度朝向；`Idle` 保持。
- **只在边沿脏**（开始/停止移动、动作切换）⇒ 流量极低，且只对"该客户端可见"的单位复制（走 `UAsceUnitReplicator` 的 LOD + 队伍视野裁剪）。
- **确认机制**：服务器接受技能后会写 `FAsceActionFragment` ⇒ 这里的边沿复制到达即客户端的"**隐式确认**"；显式回执只用于**拒绝**（逐单位、带原因）。
- **不做时长同步（v1）**：客户端动画与服务器时间线"各算各的"、按状态边沿硬切，不引入时长/起始时间字段（将来要"动画与结算逐帧对拍"再加）。

## 7. 动画（Bone 模式 / AnimToTexture）

- **技术选型：Bone 模式**（把骨骼矩阵逐帧烘成贴图、材质里 GPU 蒙皮）——素材按**骨架**共享：
  同一骨架下所有 static mesh（换皮/变体）共用一份烘焙；网格需带蒙皮权重、材质用 Bone Animation 采样。
- **数据分层**（技能与单位解耦；**定稿见 §7.2**）：
  - 动画的**语义**放**单位 def**（无动作状态：`IdleAnim/MoveAnim/DyingAnim`）与**各动作的 `CastConfig`**（攻击 = `AttackCastConfig.CastAnim`；技能 = 施法/持续动画）；
  - 每个骨架一份 **AnimSet**（**纯动画库，不懂游戏语义**）：
    `{ Skeleton + 烘焙参数 + 共享动画纹理/Pages + Meshes[] + Clips }`；
    `Clips: TMap<TSoftObjectPtr<UAnimSequence>, FAsceAnimClip{ AnimIndex, StartFrame, EndFrame }>`（**键=资产引用**，查找走 `FSoftObjectPath`，不加载资产）；
  - **没有配置就不播**（`bValid=false`）：不再有保留名/回退链；通用动画靠配置侧**显式复用**同一条资产；
  - ⚠️ 本节旧版"保留 clip 名 + 回退链"已废弃，见 §7.2。
- **运行时解析**：`(单位 AnimSet, ActionDefId, State) → 动画资产 → FAsceAnimClip → ISM per-instance custom data`
  （**2 floats：`Frame, PrevFrame`**，帧为烘焙贴图内**绝对帧**）；`Counter`/`ActionState` 边沿 → 重置到 `StartFrame` 播一次。
- **硬切**：动画按自己的时长/速度播，动作状态边沿（复制）到达即硬切；v1 不做拉伸对齐、不做跨动画混合。
- 单位类型 → `AnimSetId`（客户端解析用）：**已定：复制 `UniqueTypeId`（uint16）**，客户端用本地单位 def 表映射（顺带供检视器/UI）。
- 高 `PlayRate` 会导致跳帧 ⇒ 数据侧夹上限；持续施法用循环段。

- **播放模式 = 手动帧（已定）**：每帧由 `UAsceCombatVisualProcessor` 计算
  `Frame = StartFrame + (Now - StartTime) * FrameRate * PlayRate`（loop 取模 / 单向 clamp），写进 per-instance
  custom data **2 个 float = `{Frame, PrevFrame}`**（`Frame` 可小数 ⇒ 材质做帧间插值）；
  **clip 解析只在动作边沿**（`Counter`/`ActionState` 变化）做。
  - 为什么不用 AutoPlay：手动帧的**帧号由我们决定**（图集内绝对帧、精确、可与结算/事件对齐，且不受两端时钟漂移影响）；
  - 代价：每帧为**可见单位**写 2 个 float（query 用 `SetChunkFilter(AreAnyEntitiesVisibleInChunk)` ⇒ 只算可见单位；
    而 MassRepresentation 本来每帧就要上传可见实例的 custom data 缓冲 ⇒ 边际成本小）；
  - 约束：必须与 `UMassUpdateISMProcessor` 的**匹配集/实体顺序一致**（本处理器自己的 fragment 全 Optional）；
    顺序上必须显式 `ExecuteBefore(UMassUpdateISMProcessor)`（要读旧的 `PrevLODSignificance`）；
    且必须**覆盖每一个进 ISM 更新的实体**（否则缓冲错位）；
  - 将来想省 CPU 可加 `bUseAutoPlay` 开关（边沿写 4 float、材质自推进），共用同一份边沿解析逻辑。

### 7.1 动画纹理的显存与分页规则（决策记录）

**占用公式**（8bit；位置 + 旋转两张）：
```
每帧占：BoneRowsPerFrame = ceil(NumBones / Width) 行 × Width 列
一个动作 ≈ 帧数 × 骨骼数 × 4B               （帧数 = 动作时长 × SampleRate）
一个骨架 ≈ Σ(各动作帧数) × 骨骼数 × 4B × 2   （烘焙另多写 1 帧）
```
- **骨骼数与帧数都是乘数**（骨骼按整个骨架计费——哪怕这个动作只动了 3 根骨头）⇒ **降 `SampleRate` 是性价比最高的省显存手段**；
- 实测：60 骨骼 × 6000 帧 ≈ 2.9MB；200 骨骼 × 6000 帧 ≈ 9.6MB ⇒ **不做页级按需加载**（骨架级按需足够，见下）。

**尺寸与分页规则**：
- 一页容量 `C ≈ MaxHeight / BoneRowsPerFrame − 1`（减 1 = 烘焙多写的那帧）；页数 `K = ceil(总帧数 / C)`；
- **尺寸按实际需要**：`Width ≈ 骨骼数（对齐）`、`Height = C`；**绝不用 4096×4096**（会把每片从 ~1MB 变成 67MB）；**mip 关闭**（VAT 按精确 texel 采样）；
- 同页内段与段**零间隔**（烘焙默认：`StartFrame = NumFrames; NumFrames += 段帧数`）⇒ 空白只在**每页末尾**；
- 规则一：总帧数**只是略超** `C`（如 4200 vs 4096）⇒ **优先降 `SampleRate`/裁动作压回一页**（多开一页要付整页代价）；
- 规则二：必须多页时**均衡装箱**（按段帧数贪心），把浪费压到只剩尾页零头；
- 规则三：**禁止"一个动作跨页"**（段表碎片化 + 材质里要做分段/循环跨页映射，收益只有"尾页空白"）⇒ 不值得。

**万一真要分页**（手动帧版）：每页作为 `Texture2DArray` 的一个 slice，逐实例 custom data 扩成
`{ PageIndex, Frame, PrevFrame }`（3 个 float，`NumCustomDataFloats` 至少 3；材质按 `PageIndex` 选 slice 再按 `Frame` 采样）；
与 §7 的对接：分页时 `FAsceAnimClip::AnimIndex` 解释为 **slice 索引**（页内帧范围仍在 `StartFrame/EndFrame`）。
- **否决**"每页一个 MI/ISMC + 单位搬家"：`RemoveInstance` 会引发实例数组重排与渲染状态重建（成群搬家打帧尖峰）、组件数 ×K ⇒ draw call 变多、
  异步加载 ⇒ 首播延迟/抖动；而收益只是"没在播的页"，量级本来只有几 MB。

**烘焙流程（不需要改造插件）**：插件公开入口只有 `UAnimToTextureBPLibrary::AnimationToTexture(DA)`（一次全烘，输出写进 **DA 引用的纹理/SM**）⇒ 工具流程：
1. **每页一次**：建临时 DA（`AnimSequences` = 该页的段、**填满相同帧数**、输出指向该页纹理）→ 烘焙 → 记录页内帧段；
2. **每网格一次**（薄烘）：临时 DA（`AnimSequences` = 1 条 1 帧 —— **权重与动画无关**；位置/旋转输出指向临时纹理、权重输出指向 `T_i`）→ 烘焙 → 记录 `{SM_i, T_i}`；
3. 各页纹理打包成 `Texture2DArray`（不分页就直接用）→ 写进 **AnimSet**（§7）→ **删临时 DA 与临时纹理**（纹理/SM 是独立资产，删 DA 不影响）。
- 待确认：`GetBonePositionTexture()` 等访问器是"有则用 / 为空则自动创建资产"（决定要不要预先建纹理资产）。

**廉价按需（保留）**：AnimSet 做成 `PrimaryDataAsset` ⇒ 地图上没这个兵种就不加载（**骨架级**、无搬家/无抖动）。

### 7.2 动画解析与配置（定稿：动画层不懂游戏语义）

**分层**
```
AnimSet（骨架级）= 纯动画库：{ Skeleton, 烘焙参数, 共享动画纹理+Pages, Meshes[], Clips }
    Clips: TMap<TSoftObjectPtr<UAnimSequence>, FAsceAnimClip{ StartFrame, EndFrame }>   ← 键=资产引用、值=帧段
单位 def（兵种级）= 无动作状态的常驻语义：IdleAnim / MoveAnim / DyingAnim
各动作的 CastConfig（动作级）= 该动作的动画：攻击 = AttackCastConfig.CastAnim；技能 = CastConfig 的 Cast/Channel 动画
（**没有独立的"状态→动画"表**：动画只跟"动作状态的来源"绑定，避免同一件事写两处）
```

**规则（已定，替代旧的"保留名 + 回退链"）**
1. **没有配置就没有动画**：解析不到 ⇒ `bValid = false`，该单位此状态**什么都不播**（不再猜"通用动画"）；
2. **通用动画 = 配置侧显式复用**：某动作没专属动画，就在该动作的 `CastConfig` 里直接选同一条资产（如 `AS_Human_Cast_Generic`）；

5. **`BasePlayRate` 取消**：速度由播放方给（服务器 `PlayRate` / 技能配置）；
6. `FAsceAnimClip` 瘦成 `{ StartFrame, EndFrame }`（`AnimIndex` 仅调试用，可留可删）；

**④ 客户端预测 + 拒绝回执** —— ✅ **已实现**（下述是落地形态）：

- **不新增 fragment**：预测 = 在客户端**直接写 `FAsceCombatVisualFragment`**（`Casting + ActionDefId + Counter++ + FacingQ`）。
  它本来就是客户端动画/转身的驱动源；权威动作态边沿到达会**整段覆写**它 ⇒ **天然就是"隐式确认/取消"**，不需要额外对账状态。
  落地：`AsceOrderChannelComponent.cpp` 匿名命名空间的 `PredictSkillOrderLocally`（与服务器**同序**校验：槽位/技能表/CastConfig/CD/蓝/目标关系/射程；
  客户端没有迷雾（只有复制过来的实体）⇒ 可见性天然满足；CD 用 `AsceClientIsSkillCooldownReady`，客户端侧是**回绕百分秒值**）。
- **指令始终照发**：本地校验只决定"要不要预测"（`RequestSkillOrder` 里 `NM_Client` 门控）。
- **一次请求一条拒绝 RPC**：`ClientRejectSkillOrder(OrderSequence, TArray<FAsceEntityReject>{NetID, Reason})` —— 与
  `ServerRequestSkillOrder`（一次请求一条、带 N 个实体）**对称**；服务器把每处失败原因收集进数组、循环后统一发（空数组不发）。
  客户端按 `OrderSequence` 取预测快照（`UAsceOrderChannelComponent::PredictedSkillUnits`：预测时记录预测前的视觉字段 +
  预测写入的 `Counter`），逐条**恢复预测前的视觉态**；**服务器权威优先**：`Counter != 预测值` 或状态已不是 `Casting`
  （权威动作态已同步下来）⇒ 跳过恢复，不覆盖新状态。整批拒绝（`ClientRejectWholeOrder`）同样走这条恢复。
  - 一批里"有的能放有的不能放"⇒ 只有失败的那些进数组；没进的 = 服务器接受了 = 等动作态边沿确认。
- **不做超时**：每个单位必有结果（接受⇒动作态边沿；拒绝⇒可靠回执）。**接受"确认瞬间硬切/重播"**（文档本来就定"各算各的、到点硬切"）。
- **不做 per-entity 预测序号**：连续 N/N+1 时迟到的 reject(N) 可能清掉 N+1 的预测 —— 只是表现、最多闪一下，按"偏了就偏了"接受。
