# 技能与动作系统设计（Asce RTS）

> 状态：**设计定稿**（待实现）
> 相关：`建筑系统设计.md`、`Ether系统设计.md`、`Vision/视野与迷雾系统架构设计.md`、`Networking/*`（复制能力）、`UI/UI.md`
> 说明：攻击（自动）与技能（主动）**共用同一套动作状态机与动画/复制管线**，所以攻击规则也写在本文件里。

## 1. 目标与边界

- **主动技能**：玩家操作释放，共 **3 个槽位**（1/2/3 ↔ Q/W/E）。
- **被动技能**：v1 **只做常驻属性加成**（在 def 层改属性），不做事件触发。
- **释放前必须停下**：收到技能指令的单位**无条件先停止移动**——即使该单位这个技能放不出来（射程不够/没蓝/CD/槽位为空）也要停，
  否则"框选一堆移动中的单位放技能，有的放有的还在走"非常诡异；同时"停下"也是给玩家的**指令回执**（否则玩家分不清是没点到还是放不出来）。
- **服务器权威**：目标解析、射程/可见性校验、CD、蓝耗、结算、生成物**全部在服务器**。
- **客户端不预测技能**：不做 RPC 预测、不做逐单位拒绝回执；表现**全部由状态复制驱动**。
- **生成物也是 Mass entity**：创建必须**排队 → 下一帧的生成阶段**（项目不变式：实体创建/销毁必须在模拟阶段 2 之前）。
- **不移动施法 / 不追击**：射程不够就直接不释放，不走过去。

## 2. 数据模型

### 2.1 技能定义（静态，数据表）

```cpp
FAsceActionDef   // 表里也放"攻击"这一行（见 §1：攻击 = 内置动作定义）
{
    int32  Id;
    uint8  Type;              // Active / Passive
    uint8  CastKind;          // Instant(瞬发) / Cast(普通施法) / Channel(持续施法)
    uint8  TargetKind;        // None / Point(非指向) / Unit(指向)
    uint8  Delivery;          // Instant(直接生效) / Projectile(弹道) / SpawnAtTarget(在目标位置生成)
    float  Range;             // 施法距离（cm）
    uint8  RangeKind;         // 距离口径（与攻击同一套：近战=表面距离；远程=低→高表面、高→低圆心）
    float  CastTime;          // 普通施法前摇时长（动作自然时长）
    float  ChannelDuration;   // 持续施法总时长
    float  ChannelTickInterval; // 持续施法的周期结算间隔
    float  Cooldown;          // 冷却
    float  ManaCost;
    int32  ProjectileDefId;   // 弹道实体定义
    int32  SpawnGroupId;       // 生成物组定义（召唤/地面效果）
    FAsceAnimSegment Anim;     // 动画段（StartFrame/EndFrame/bLoop/PlayRate 规则）
};
```

- **攻击 = 内置动作定义**（自动触发、无蓝耗），与技能共用"占时 → 结算 → 打断"管线（见 §4）。

### 2.2 实体：技能槽位（真实数据，且要复制到客户端）

```cpp
USTRUCT() struct FAsceSkillSlot
{
    int32  SkillId = 0;              // 0 = 空槽
    double NextReadyServerTime = 0;  // 下次可释放的**服务器世界时间**（CD）
};

USTRUCT() struct FAsceSkillSlotsFragment : public FMassFragment
{
    FAsceSkillSlot Slots[3];
};
```

- **槽位是真实数据不是 UI**：指令里只带槽位号，服务器按"该单位这个槽位是什么技能"解析（因此一条指令就能让多单位同时放不同技能）。
- **技能状态（CD 等）存在槽位里** ⇒ 玩家交换槽位时，技能**连同它的 CD** 一起换位（不重置）；蓝耗/等级等运行时数据同理。
- 为"**单位自定义技能**"（每单位不同槽位内容）预留了空间。
- 配置指令：`SetSkillSlot(SelectedNetIDs, SlotId, SkillId)`；服务器校验该单位**确实拥有**该技能 + `NotOwned`。

### 2.3 实体：动作/战斗运行时（服务器专有，不复制）

```cpp
USTRUCT() struct FAsceCombatFragment : public FMassFragment   // 挂载 = 该实体能主动攻击；不挂 = 只能被打
{
    // 静态（来自 def）
    float AttackRange; float AttackDamage;
    float BaseAttackTime;    // 攻击动作自然时长
    float AttackSpeed;       // PlayRate = AttackSpeed / 200 + 0.1（180 → 1.0x）
    uint8 RangeKind; uint8 bAutoAttack : 1; uint8 bProjectile : 1;
    int32 ProjectileDefId;

    // 运行时
    FMassEntityHandle DesignatedTarget;  // 指定目标（持久，失效即清）
    float  NextScanTime;                 // 0.3s 节流扫描
};

USTRUCT() struct FAsceActionFragment : public FMassFragment      // 当前动作（唯一真相）
{
    uint8  ActionState;        // Idle/Move/Attack/Cast/Channel/Dying
    int32  ActionDefId;        // 攻击=内置 id；技能=SkillId
    double ActionEndTime;      // 动作结束（服务器世界时间）
    double NextReadyTime;      // 本动作的 CD 结束（攻击专用；技能记在槽位上）
    FMassEntityHandle ActionTarget;
    float  FacingYaw;          // 本次动作朝向（动作开始时定死）
    double NextTickTime;       // Channel 的周期结算
    uint32 Counter;            // 递增序号（每次"下发一次动作"++，供客户端播一次）
};
```

## 3. 指令流

### 3.1 技能释放指令

```cpp
FSkillOrder { uint8 SlotId; FVector2D TargetPos; FMassNetworkID TargetNetID /*可无效*/; TArray<FMassNetworkID> SelectedNetIDs; }
```

- 客户端**只发槽位号**，不解析技能；目标类型由服务器按槽位里的技能 def 决定。
- 客户端**统一带上** `TargetPos` 与 `TargetNetID`（后者可能无效）：非指向技能用 Pos，指向技能用 NetID。
  **不做客户端拦截**——指向技能点到空地也照发（服务器拒绝，但单位照样停下 ⇒ 玩家得到反馈）。
- 服务器逐单位处理：
  1. **无条件停止移动**（清移动命令、速度清零）；
  2. 校验：槽位非空？CD 到？蓝够？目标合法（TargetKind 匹配；指向目标**必须可见**；友/敌符合 def；**在射程内**——距离口径按 def 的 RangeKind）？当前动作是否允许被技能打断（**技能优先级最高，可打断攻击**）？
  3. 通过 ⇒ 进入动作：**设朝向面向目标**，进入 `Cast`（播前摇动画）或 `Channel`；
     **cost / CD / effect 一律在"真正释放"那一刻处理**（见 §5）——**进入动作时不扣蓝、不写 CD**；
  4. 不通过 ⇒ 单位停在原地（保持 Idle / 自动攻击照常）。
- **没有预测、没有回执**：玩家靠"单位停下 + 随后的动作/特效"判断是否生效。

### 3.2 停止指令（S）

- `S` = 向当前选中单位发送**停止指令**：停止移动 + 取消正在进行的施法（含持续施法，**已生效的周期效果保留**）→ 回到 `Idle`。
- **不影响自动攻击**：攻击只受"是否开启自动攻击"这个开关调控（停止指令不关它）。
- 这是**唯一**的主动取消手段（见 §4 打断矩阵）。

## 4. 动作状态机与打断矩阵

状态：`Idle / Move / Attack / Cast / Channel / Dying`。同一时刻**只有一个动作**。

| 当前 \ 事件 | 移动指令 | 技能指令 | 停止(S) | 死亡 |
|---|---|---|---|---|
| **Attack** | 打断（不结算） | 打断 → 施法 | 打断 | 打断 |
| **Cast** | **不打断** | **打断**：新技能可释放 → 顶掉当前施法（不结算）改放新技能；不可释放 → 维持原施法 | 取消 | 打断 |
| **Channel** | **不打断** | **打断**：同上（已生效的周期效果保留；未结算的丢弃） | 取消（保留已生效） | 打断 |
| **Move** | 替换 | 停止移动 → 施法 | 停止 | 打断 |
| **Idle** | 进入 Move | 施法 | —（保持 Idle，自动攻击照常） | 打断 |

- **施法不能被移动打断**（规则已定），但可以被 `S`、**新的技能指令**（见下）、死亡终止。
- 施法期间单位**静止**；施法结束回到 `Idle`（随后自动攻击自行接管）。
- **施法前摇期间目标死亡不取消施法**：前摇照常播完，到"真正释放"那一帧发现目标不存在 ⇒ 什么都不做（见 §5）。
- **施法中收到新的技能指令**（手感优先）：先对新技能做**完整校验**——能放就**直接顶掉**当前施法并改放新技能（不需要玩家先按 `S`）；放不了就**维持原状态**（继续原施法）。
  被顶掉的施法**不结算**；**费用**：`Cast` 被顶掉时还没到"真正释放" ⇒ **根本没扣蓝、没落 CD**；`Channel` 从开始就算"真正释放" ⇒ 蓝/CD **已支付且不返还**（已生效的周期效果保留）。
- "**无条件停止移动**"是对"正在移动的单位"的公共动作（施法者本来就静止）；上面的"维持原状态"只针对"施法动作是否被顶掉"。

## 5. 结算

- **Cast（普通施法）**：前摇 `CastTime` 期间**只是播动画**（还没"真正释放"）→ **前摇结束那一帧才是真正释放**：
  这一帧**先处理 cost 与 CD**（扣蓝、写 `Slots[i].NextReadyServerTime = now + Cooldown`），**再结算 effect**（生成弹道 / 在目标位置生成 / 直接生效）。
  结算时**只需再查一次"目标是否还存在"**：存在 → 生效；不存在 → **什么都不做**（不生成、不补刀）。
  若这一帧蓝已不够（前摇期间被扣蓝）→ **释放失败**：不扣、不落 CD、不生成，回 `Idle`。
- **Channel（持续施法，无前摇）**：**开始那一刻就是"真正释放"** ⇒ 立刻扣蓝 + 落 CD（`Slots[i].NextReadyServerTime = now + Cooldown`），
  然后循环播动画、每 `ChannelTickInterval` 结算一次，直到 `ChannelDuration` 结束 / 被取消 / 死亡；**被打断保留已生效效果、蓝/CD 不返还**。
- **弹道**：
  - 生成位置 = 施法者**前方**（`pos + forward * SpawnOffset`）；
  - 指向性（Unit）：**追踪目标直到命中**（命中用**距离阈值**，不做物理碰撞）；**目标中途死亡 → 弹道直接消失**；
  - 非指向性（Point）：直线飞向目标点。
- **生成物排队**：结算当帧只入队，**下一帧生成阶段**创建实体（弹道/召唤/地面效果）。
- **迷雾**：不对雾内目标施法（客户端本来就没有视野外单位的 NetID ⇒ 天然防隔雾狙击）；服务器再做一次可见性兜底。

## 6. 复制通道

### 6.1 动作态通道（驱动动画；详见战斗同步讨论）

```cpp
USTRUCT() struct FAsceActionReplicatedAgent : public FReplicatedAgentBase
{
    uint8 ActionState;    // Idle/Move/Attack/Cast/Channel/Dying（**全部由服务器发**）
    uint8 ActionDefId;    // 攻击=内置 id；技能=SkillId（客户端据此查动画段/时长）
    uint8 ActionCounter;  // 递增：变了 → 客户端"播一次"
    uint8 PlayRateQ;      // 播放速度量化（0.1~2.0）
    uint8 FacingQ;        // 本次动作朝向（0..255 → 360°）
};
```

- **`Idle/Move` 也由服务器发**（不让客户端从速度推断）：状态与朝向在**同一个 USTRUCT**里一次到达，不依赖跨通道顺序
  （否则会出现"服务器已停+攻击，但速度/位置通道还慢一帧，客户端以为自己在 Move"）。
- 客户端规则：`ActionCounter` 变 → 播一次；回 `Idle` → **硬切**；`Dying` → 播死亡；`Move/Idle` 循环。
- 朝向：`Attack/Cast/Channel` 用 `FacingQ`；`Move` 用本地速度朝向；`Idle` 保持。
- **只在边沿脏**（开始/停止移动、动作切换）⇒ 流量极低，且只对"该客户端可见"的单位复制（走 `UAsceUnitReplicator` 的 LOD + 队伍视野裁剪）。

### 6.2 技能面板通道（驱动 UI）

```cpp
USTRUCT() struct FAsceSkillPanelReplicatedAgent : public FReplicatedAgentBase
{
    int32  SkillId[3];              // 槽位配置（顺序即玩家配置；换槽 = 整组复制）
    double NextReadyServerTime[3];  // 每槽 CD（**服务器世界时间戳**）
};
```

- 玩家改槽位时服务器整组复制到客户端；**技能数据（含 CD）随槽位** ⇒ 客户端能显示图标与 CD 倒计时。
- **时钟**：客户端用 `AGameStateBase::GetServerWorldTimeSeconds()` 与时间戳对比。**CD 判定永远在服务器**，
  所以"玩家改本机系统时间"既不能绕过 CD、也只会影响自己的 UI。

## 7. 动画（VAT）

- 动画段由 `(ActionDefId, ActionState)` 查**客户端表** → `(StartFrame, EndFrame, bLoop)`；`PlayRate` 由服务器下发（`PlayRateQ`）。
- 动作时长（`CastTime`/`ChannelDuration`）是静态 def，两端一致 ⇒ 不用重复下发；运行时只同步"开始（Counter）+ 速度"。
- 高 `PlayRate` 会导致 VAT 跳帧 ⇒ 在数据侧夹上限；持续施法用循环段。
