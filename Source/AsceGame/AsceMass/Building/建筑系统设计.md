# 建筑系统基础设计

> 范围：本设计只覆盖"建筑怎么落地（装配）+ 运行期增删"的最小闭环。
> **实体表现**（怎么渲染）与**存档**后续统一做，这里只留接口位；建造菜单/成本属于 UI + 配置层，另做。

---

## 1. 现状与硬约束（已被其它系统依赖，不能随意改）

建筑在本项目里不是一个新概念，它已经被下面这些系统"用"着：

- **建筑 = Mass 实体**（静态实体，**不进** 单位层，不做移动积分）：
  - 标记 `FAsceGridFootprintFragment`（`AsceMass/Fragments/AsceFootprintFragment.h`）+ `FAsceBuildingTag`（`AsceMass/Fragments/AsceCoreFragments.h`）；
  - `FAsceGridFootprintFragment{ OriginGridLocation, SizeX, SizeY, OcclusionHeightCm }`；逻辑格边长 100cm（`GRID_SIZE`）。
  - **旋转语义（既有约定，必须遵守）**：`OriginGridLocation + SizeX/SizeY` 就是**旋转后的最终 AABB** —— `AsceCostFieldFootprintObserverProcessor` 和 `AsceVisionOcclusionObserverProcessor` 都是直接按矩形逐格遍历、**不做任何旋转数学**；建筑层/射线也按这个矩形。朝向（"建筑朝哪")另外放在实体 Transform 上。
- **建筑类型数据**在**实体定义表**（`AsceEntityDefRow`，见 `AsceMass/Data/AsceEntityDefTypes.h`）：
  行名 = 数字 ID，`Def = FAsceEtherBuildingDef`（含建筑专有的 `SizeX/SizeY/OcclusionHeightCm` +
  `DeviceType/ProcessCoreClass/SupportedDimCount/PortSlots/DefaultInternalLinks`）。
  实体挂 `FEtherBuildingFragment{ BuildingDefId }` + `FAsceUnitDefFragment{ UniqueTypeId }`（uint16，= 行名数字）；
  - Ether 侧按 `BuildingDefId` 查表（`UAsceEntityDefLibrary`），`AsceEtherRegistrationObserverProcessor` 观察
    `FEtherBuildingFragment` 的 Add/Remove ⇒ **push `AddNode` / `RemoveNode` 命令**。
- **实体的创建/销毁会自动触发副作用链**（不需要建筑系统手动调）：
  - `AsceCostFieldFootprintObserverProcessor`：改寻路 costfield；
  - `AsceVisionOcclusionObserverProcessor`：写视野遮挡矩形；
  - `UAsceGridBuildingsUpdateProcessor`：下一轮 grid 阶段把建筑收录进**建筑层**（`RunGridStages` 内部）。
- **网格初始化入口**在 `AAsceWorldMapReplicatorActor`（`ConstructGrid` + `Fog->InitializeVisionMap`）。
- 调度顺序见 `Ether系统设计.md` 步骤⑬：**Mass PrePhysics observer（结构变化）→ 阶段1 流场 → 阶段2 空间数据 → … → 阶段5 Ether drain**。

**已查出的两处缺口**（本次要补）：
1. `ConstructBuildingsGrid` **没有任何调用者** ⇒ 真跑游戏时建筑层从不构建；
2. 除 `AAsceEtherDebugger`（调试用）外，**没有代码写 footprint** ⇒ 没有真实建造入口。

## 2. 决策表（已拍板）

| # | 决策点 | 结论 |
|---|---|---|
| 1 | 旋转语义 | 作者摆的是**未旋转**尺寸 + 朝向 `Rotation`（0~3 = 顺时针 90° 次数，绕 footprint 中心）；落库时换算成**旋转后的最终 AABB** 写进 footprint（与 costfield/视野/建筑层同口径），朝向写进实体 Transform（Ether 已接：`CachedDirection` + `SlotToCell` 按它旋转） |
| 2 | 重叠 | **不允许**。权威端在"创建真实 entity 时"校验（防作弊的最终防线）；非权威端在放置时也提前校验（UI 体验） |
| 3 | 搬家语义 | **拆 + 建**（走既有增删链，连带 costfield/vision/建筑层/Ether 全自动；代价是端口在制品丢失） |
| 4 | 改造入口 | 统一走 `UAsceBuildingSubsystem`（`PlaceBuilding` / `DemolishBuilding`），内部"改 fragment + push Ether 命令"；**不需要额外生产者阶段**（唯一 drain 点已兜住顺序） |
| 5 | 引导顺序 | `ConstructGrid` → `ConstructBuildingsGrid` → 地图/流场就绪 → **引导阶段**批量创建预摆建筑 |
| 6 | 权威 | **服务器权威**：只有服务器创建/销毁实体；客户端只表现（表现来自复制过来的实体，后续统一做） |
| 7 | 预摆来源 | 关卡里直接摆 `AAsceBuildingPlacementActor`（沿用 Ether 调试器那套"带初值建实体"的模式），BeginPlay 向子系统注册，引导阶段创建实体后**两端都销毁这些 Actor** |
| 8 | 存档 | 后续统一做（本设计只保证"建筑集合可从摆放数据重建"） |

## 3. 数据模型

### 3.1 摆放 Actor `AAsceBuildingPlacementActor`

| 字段 | 说明 |
|---|---|
| `BuildingDef` (`FAsceRowNameWrapper`，`meta=(DataTableBinding="AsceEntityDefRow:...")`) | 建筑类型（实体定义表行名 = 数字 ID；编辑器下拉选行） |
| `TeamKey` (`int32`) | 归属阵营（写进 `FAsceTeamFragment::TeamKey`） |
| （Actor 位置 + 旋转） | 位置 = footprint **中心**（吸附到逻辑格中心）；`Rotation = round(Yaw / 90) % 4` |
| `bEnabled` | 地图作者临时禁用某建筑（不创建） |

**格子换算**（`Size = (SizeX, SizeY)` 来自定义表 = **未旋转**尺寸；`Rotation` 0~3）：
```
CenterCell = floor(ActorLocation / GRID_SIZE)          // 所在逻辑格 = footprint 中心格
Rotation   = ((round(Yaw / 90) % 4) + 4) % 4
OriginGridLocation = CenterCell - floor((Size - 1) / 2)   // 未旋转 footprint 的最小角

// 落库时换算成最终 AABB（rotation 为奇数 ⇒ 长宽对调，中心不变）：
RotatedSize = (Rotation % 2 == 1) ? (Size.Y, Size.X) : Size
FootMin = GetCenterCell() - (RotatedSize - 1) / 2      // 见 FAsceBuildingPlacement::GetOccupiedBounds
FootMax = FootMin + RotatedSize - 1
```
> 换算统一走 `FAsceBuildingPlacement::GetOccupiedBounds()`，避免各处自己算导致 1 格偏移。

### 3.2 建筑实体（创建时的初值，一次给全）

```
FTransformFragment          // 位置 = footprint 几何中心（Z = 0，后续接高度场再调）；朝向 = Rotation × 90°
FAsceGridFootprintFragment  // OriginGridLocation/SizeX/SizeY = **最终 AABB**（旋转已折进去）；OcclusionHeightCm 来自配置
FAsceBuildingTag            // （tag）建筑层筛选
FEtherBuildingFragment      // BuildingDefId
FAsceTeamFragment           // TeamKey
```
> 必须**创建时就填好初值**（`CreateEntity(实例表)` 或 Trait 路径），因为 Mass 的 Add 观察者在创建时立即执行，走裸 Archetype 会让观察者读到空值。
> `FAsceBuildingTag` 在"实例表创建"路径上无法一次带上（引擎 `CreateEntity(TConstArrayView<FInstancedStruct>)` 只吃 fragment），创建后补 `EM.AddTagToEntity(...)`。

## 4. 流程

### 4.1 编辑器摆放（地图构建者）
- 拖一个 `AAsceBuildingPlacementActor`，设置类型 / 旋转 / 阵营；
- Actor 在编辑器里用一个方块标记显示实际占格（游戏中隐藏），并把位置/朝向吸附到逻辑格与 90°；
- 不参与烘焙（Bake 只烘地形/遮挡/高度，建筑在运行时创建）。

### 4.2 运行时注册（两端）
- `AAsceBuildingPlacementActor::BeginPlay` → `UAsceBuildingSubsystem::RegisterPlacement(*this)`（服务器/客户端都注册，只有服务器会真的建）。

### 4.3 引导阶段（服务器；一次性）
`UAsceBuildingSubsystem::RunBootstrapStage()`，作为调度器**阶段 0**（在阶段 1 之前；`bBootstrapped` 或 `PendingPlacements.Num() == 0` 时直接早退，零开销）：

1. **就绪条件**（不满足就本帧不动，等下一帧）：
   - `SpatialGrid->IsBuildingsGridReady()`（新增，`BuildingCells.Num() > 0`）；
   - 是权威端（`GetNetMode() != NM_Client`）；
   - Ether 子系统可用（`UAsceEtherNetworkSubsystem::Get`；定义数据从实体定义表查，无需登记）。
2. 逐个处理摆放项：
   - **校验**（见 §5）→ 失败：警告日志 + 跳过（并销毁该 Actor）；
   - 成功：创建建筑实体（§3.2 初值）→ 记入 `Buildings` 列表（Entity ↔ Placement 反查，供后续拆除）× ；
3. 全部处理完 ⇒ `bBootstrapped = true`；**销毁所有摆放 Actor**（两端都销毁：客户端不建实体，但同样销毁 Actor，避免出现"假建筑"；建筑表现后续由实体复制负责）。

### 4.4 运行期增删（服务器权威）

```cpp
// UAsceBuildingSubsystem
bool PlaceBuilding(const FAsceBuildingPlacement& Placement, FString* OutError);
bool DemolishBuilding(FMassEntityHandle Building);
```
- `PlaceBuilding`：校验 → 建实体（连带 observer 链生效，Ether 自动 `AddNode`）→ 广播/复制到客户端（走统一的实体复制/表现，后续做）。
- `DemolishBuilding`：销毁实体（Ether 自动 `RemoveNode`，costfield/vision/建筑层自动复原）。
- 客户端请求：先在本地做一遍校验（立即反馈），再发 RPC；**服务器重做校验**（唯一真相）。
- **搬家 = `DemolishBuilding` + `PlaceBuilding`**（不提供"原地改 footprint"的接口，避免增量漏项）。

### 4.5 引导顺序（世界初始化）
```
AAsceWorldMapReplicatorActor::BeginPlay
  ├─ SpatialGrid->ConstructGrid(...)                 // 单位层
  ├─ SpatialGrid->ConstructBuildingsGrid(WorldEnd/100, 100, 4)   // ★ 本次新增：建筑层
  ├─ Fog->InitializeVisionMap(...)
  └─ (地图/流场/Bake 数据就绪)
调度器 Tick
  ├─ 阶段 0：UAsceBuildingSubsystem::RunBootstrapStage()   // ★ 本次新增：预摆建筑落地
  ├─ 阶段 1：流场/寻路
  ├─ 阶段 2：空间数据（建筑层收录本帧新建筑）
  ├─ 阶段 3：移动
  ├─ 阶段 4：视野/雾
  ├─ 阶段 5：Ether drain → 模拟
  └─ 阶段 6：雾渲染上传
```

## 5. 校验规则（不许重叠）

权威端在**创建 entity 前**校验（`ValidatePlacement`）：

1. **定义有效**：`BuildingDefId` 非空，且能在实体定义表里查到 `FAsceEtherBuildingDef`（`UAsceEntityDefLibrary`）、`SizeX/SizeY >= 1`；
2. **越界**：旋转后的占用格必须全部落在建筑网格范围内；
3. **重叠**：把最终 AABB 交给建筑层查相交：`SpatialGrid->FindBuildingsInLogicalRect(Min, Max, Hits)`（内部按粗格筛 + 逐建筑 AABB 判交，Entity 去重）—— 有命中即**拒绝**；
4. （后续）资源/前置/地形限制（成本、可建造地形等）。

非权威端放置时用**同一套** `ValidatePlacement`（纯查询、无副作用）提前校验，服务器端再校验一次（防作弊）。

## 7. 实施步骤（每步一个编译点）

1. ✅ **建筑层就绪条件 + 构建**：`IsBuildingsGridReady()`；`AAsceWorldMapReplicatorActor` 补 `ConstructBuildingsGrid`（逻辑格 = 流场格 100cm，粗格 4）。
2. ✅ **摆放 Actor**：`AAsceBuildingPlacementActor`（字段 + 编辑器占格标记 + 吸附 + BeginPlay 注册）。
3. ✅ **子系统 + 引导阶段**：`UAsceBuildingSubsystem`（Pending / `ValidatePlacement` / 创建实体 / 销毁 Actor / 日志），调度器接阶段 0。
4. ⏳ **运行期增删**：`PlaceBuilding` / `DemolishBuilding`（已实现，待接客户端请求 RPC + 控制台命令验证一次拆除全链复原）。
5. ⏳ **收尾**：`AAsceEtherDebugger` 的摆放路径改为复用 `UAsceBuildingSubsystem`（避免两套），调试器只留可视化。

## 8. 未决 / 后续

- **存档**：统一做；本设计保证"地图预摆 = 摆放 Actor（可序列化）+ 运行期增删 = 服务器事件"，都能重放出建筑集合。
