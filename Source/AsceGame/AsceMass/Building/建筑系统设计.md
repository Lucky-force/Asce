# 建筑系统基础设计

> 范围：本设计只覆盖"建筑怎么落地（装配）+ 运行期增删"的最小闭环。
> **实体表现**（怎么渲染）与**存档**后续统一做，这里只留接口位；建造菜单/成本属于 UI + 配置层，另做。

---

## 1. 现状与硬约束（已被其它系统依赖，不能随意改）

建筑在本项目里不是一个新概念，它已经被下面这些系统"用"着：

- **建筑 = Mass 实体**（静态实体，**不进** 单位层，不做移动积分）：
  - 标记 `FAsceGridFootprintFragment`（`AsceMass/Fragments/AsceFootprintFragment.h`）+ `FAsceBuildingTag`（`AsceMass/Fragments/AsceCoreFragments.h`）；
  - `FAsceGridFootprintFragment{ OriginGridLocation, SizeX, SizeY, OcclusionHeightCm }`；逻辑格边长 100cm（`GRID_SIZE`）。
  - **旋转语义（既有约定，必须遵守）**：`OriginGridLocation + SizeX/SizeY` 就是**旋转后的最终 AABB** —— `AsceCostFieldFootprintObserverProcessor` 和 `AsceVisionOcclusionObserverProcessor` 都是直接按矩形逐格遍历、**不做任何旋转数学**；建筑层/射线也按这个矩形。朝向（"建筑朝哪")另外放在实体 Transform 上。
- **建筑类型数据**在**实体定义表**（`AsceEntityDefRow`，见 `AsceMass/Data/AsceEntityDefTypes.h`）：
  行名 = 数字 ID，`Def = FAsceEtherBuildingDef`（含建筑专有的 `SizeX/SizeY/OcclusionHeightCm` +
  `DeviceType/ProcessCoreClass/SupportedDimCount/PortSlots/DefaultInternalLinks`）。
  实体挂 `FEtherBuildingFragment`（**空标记**）+ `FAsceUnitDefFragment{ UniqueTypeId }`（uint16，= 行名数字）；
  - Ether 侧按 `UniqueTypeId`（`FString::FromInt` → 行名）查表（`UAsceEntityDefLibrary`），`AsceEtherRegistrationObserverProcessor` 观察
    `FEtherBuildingFragment` 的 Add/Remove ⇒ **push `AddNode` / `RemoveNode` 命令**。
- **实体的创建/销毁会自动触发副作用链**（不需要建筑系统手动调）：
  - `AsceCostFieldFootprintObserverProcessor`：改寻路 costfield；
  - `AsceVisionOcclusionObserverProcessor`：写视野遮挡矩形；
  - `UAsceGridBuildingsUpdateProcessor`：下一轮 grid 阶段把建筑收录进**建筑层**（`RunGridStages` 内部）。
- **网格初始化入口**在 `AAsceWorldMapReplicatorActor`（`ConstructGrid` + `Fog->InitializeVisionMap`）。
- 调度顺序见 `Ether系统设计.md` 步骤⑬：**Mass PrePhysics observer（结构变化）→ 阶段1 流场 → 阶段2 空间数据 → … → 阶段5 Ether drain**。

**已查出的两处缺口**（本次要补）：
1. `ConstructBuildingsGrid` **没有任何调用者** ⇒ 真跑游戏时建筑层从不构建；
2. 除 `AAsceEtherDebugger`（调试用）外，**没有代码写 footprint** ⇒ 没有真实建造入口。

## 2. 决策表（已拍板）

| # | 决策点 | 结论 |
|---|---|---|
| 1 | 旋转语义 | 作者摆的是**未旋转**尺寸 + 朝向 `Rotation`（0~3 = 顺时针 90° 次数，绕 footprint 中心）；落库时换算成**旋转后的最终 AABB** 写进 footprint（与 costfield/视野/建筑层同口径），朝向写进实体 Transform（Ether 已接：`CachedDirection` + `SlotToCell` 按它旋转） |
| 2 | 重叠 | **不允许**。权威端在"创建真实 entity 时"校验（防作弊的最终防线）；非权威端在放置时也提前校验（UI 体验） |
| 3 | 搬家语义 | **拆 + 建**（走既有增删链，连带 costfield/vision/建筑层/Ether 全自动；代价是端口在制品丢失） |
| 4 | 改造入口 | 统一走 `UAsceBuildingSubsystem`（`PlaceBuilding` / `DemolishBuilding`），内部"改 fragment + push Ether 命令"；**不需要额外生产者阶段**（唯一 drain 点已兜住顺序） |
| 5 | 引导顺序 | `ConstructGrid` → `ConstructBuildingsGrid` → 地图/流场就绪 → **引导阶段**批量创建预摆建筑 |
| 6 | 权威 | **服务器权威**：只有服务器创建/销毁实体；客户端只表现（表现来自复制过来的实体，后续统一做） |
| 7 | 预摆来源 | 关卡里直接摆 `AAsceBuildingPlacementActor`（沿用 Ether 调试器那套"带初值建实体"的模式），BeginPlay 向子系统注册，引导阶段创建实体后**两端都销毁这些 Actor** |
| 8 | 存档 | 后续统一做（本设计只保证"建筑集合可从摆放数据重建"） |

## 3. 数据模型

### 3.1 摆放 Actor `AAsceBuildingPlacementActor`

| 字段 | 说明 |
|---|---|
| `BuildingDef` (`FAsceRowNameWrapper`，`meta=(DataTableBinding="AsceEntityDefRow:...")`) | 建筑类型（实体定义表行名 = 数字 ID；编辑器下拉选行） |
| `TeamKey` (`int32`) | 归属阵营（写进 `FAsceTeamFragment::TeamKey`） |
| （Actor 位置 + 旋转） | 位置 = footprint **中心**（吸附到逻辑格中心）；`Rotation = round(Yaw / 90) % 4` |
| `bEnabled` | 地图作者临时禁用某建筑（不创建） |

**格子换算**（`Size = (SizeX, SizeY)` 来自定义表 = **未旋转**尺寸；`Rotation` 0~3）：
```
CenterCell = floor(ActorLocation / GRID_SIZE)          // 所在逻辑格 = footprint 中心格
Rotation   = ((round(Yaw / 90) % 4) + 4) % 4
OriginGridLocation = CenterCell - floor((Size - 1) / 2)   // 未旋转 footprint 的最小角

// 落库时换算成最终 AABB（rotation 为奇数 ⇒ 长宽对调，中心不变）：
RotatedSize = (Rotation % 2 == 1) ? (Size.Y, Size.X) : Size
FootMin = GetCenterCell() - (RotatedSize - 1) / 2      // 见 FAsceBuildingPlacement::GetOccupiedBounds
FootMax = FootMin + RotatedSize - 1
```
> 换算统一走 `FAsceBuildingPlacement::GetOccupiedBounds()`，避免各处自己算导致 1 格偏移。

### 3.2 建筑实体（**分两段**：创建 = 建造中；完工 = 补 footprint）

**创建时（建造中实体）**
```
FTransformFragment        // 位置 = footprint 几何中心（Z = 0）；朝向 = Rotation × 90°
FAsceUnitDefFragment      // UniqueTypeId（身份，Ether 注册靠它）
FAsceTeamFragment         // TeamKey
FAsceBuildingTag          // 模板 trait 一般已带；子系统兜底补
FAsceConstructingFragment // 建造信息：未旋转占位 + Rotation + OcclusionHeightCm + bEtherBuilding + 开工时间/工期
```
> **结构契约**：建筑 def 行的 `EntityTemplate` **必须包含 `UAsceRTSEntityTrait`**（提供 Transform / `FAsceUnitDefFragment` / `FAsceTeamFragment` 这三个"实体基础"，单位与建筑都需要）+ `UAsceRTSBuildingTrait`（加 `FAsceBuildingTag`）。
> 缺了会变成"半状态"：costfield/视野/建筑层正常（footprint 由建筑系统加），但 **Ether 注册观察者的查询不匹配 ⇒ 建筑对 Ether 完全不可见**；创建时 `ensure` 会报错（`UAsceBuildingSubsystem::CreateConstructingBuilding` / `UAsceEntityFactory`）。

> **贴地（通用机制，不在建筑系统里做）**：实体 Z 由共享的 `UAsceTerrainHeightProcessor` 负责 —— 它的查询**只要 `FTransformFragment`** ⇒ **单位与建筑（及以后任何需要贴地的实体）共用同一份双线性采样**（`FAsceVisionHeightMap::SampleHeightWorld`；图外不贴地、保持原 Z）。
> 建筑创建时 Z 先给 0，**同一帧的移动阶段**就会把它贴到地形高度（`Placement` 的实体与静态建筑都幂等）。
> 采样结果由建筑 layer 的 processor 从实体 Transform 读进 `FAsceGridBuildingPart::BaseZ`，供**选择/命中盒**（`FindBuildingHitOnRay`）从基座起算 Z（新建建筑那一帧 layer 里 BaseZ 可能还是旧值，下一帧修正）。
> ⚠️ 待定：视野遮挡高度（`OcclusionHeightCm`）的语义 —— vision 侧目前隐含"地面 = Z=0"；建筑抬高后需要明确是"**相对基座**"还是"**绝对高度**"（见 §8）。
> **不写 footprint** ⇒ costfield / 视野 / Ether 的 Add 观察者此时都不触发（**建造期不挡路**，只在放置校验里用 pending 占位）。

**完工时（`UAsceBuildingSubsystem::CompleteConstruction`，在施工阶段推进）**
```
FAsceGridFootprintFragment  // OriginGridLocation/SizeX/SizeY = **最终 AABB**（由建造 fragment 的未旋转占位换算）
FEtherBuildingFragment      // 仅 Ether 建筑（`bEtherBuilding`）
（删）FAsceConstructingFragment
```
> 完工这一刻起观察者才真正生效：costfield 写阻挡、视野写遮挡、Ether `AddNode`（下一个 Mass 阶段）。
> 完工瞬间**不释放**建造占位 —— 由 `UAsceBuildingFootprintObserverProcessor`（footprint Add 观察者）在 costfield 写完之后释放，避免"两边都不挡"的空窗。

## 4. 流程

### 4.1 编辑器摆放（地图构建者）
- 拖一个 `AAsceBuildingPlacementActor`，设置类型 / 旋转 / 阵营；
- Actor 在编辑器里用一个方块标记显示实际占格（游戏中隐藏），并把位置/朝向吸附到逻辑格与 90°；
- 不参与烘焙（Bake 只烘地形/遮挡/高度，建筑在运行时创建）。

### 4.2 运行时注册（两端）
- `AAsceBuildingPlacementActor::BeginPlay` → `UAsceBuildingSubsystem::RegisterPlacement(*this)`（服务器/客户端都注册，只有服务器会真的建）。

### 4.3 引导阶段（服务器；一次性）
`UAsceBuildingSubsystem::RunBootstrapStage()`，作为调度器**阶段 0**（在阶段 1 之前；`bBootstrapped` 或 `PendingPlacements.Num() == 0` 时直接早退，零开销）：

1. **就绪条件**（不满足就本帧不动，等下一帧）：
   - 是权威端（`GetNetMode() != NM_Client`）；
   - 世界地图数据就绪（`UAscePathFindingSubsystem` 的 `FWorldMapData`，放置校验要用）。
2. 逐个处理摆放项：
   - **校验**（见 §5）→ 失败：Warning 日志 + 跳过（**不重试**；失败的摆放项也会随 Actor 一起销毁 ✗ 这是**有意**的：
     摆放 Actor 只是运行时数据源、不是"建筑"，留它没有意义；失败清单在日志里，作者据此修关卡/配置）；
   - 成功：创建**建造中实体**（§3.2）→ 记入 `Buildings`（`bComplete=false`）+ `PendingBuilds` 占位；
3. 全部处理完 ⇒ `bBootstrapped = true`；**销毁所有摆放 Actor**（两端都销毁：客户端不建实体，但同样销毁 Actor；建筑表现后续由实体复制负责）。

### 4.4 施工阶段（服务器；每帧）
`UAsceBuildingSubsystem::RunConstructionStage()`，调度器**阶段 0b**（引导之后、空间数据之前）：
- 遍历 `PendingBuilds`：实体无效 ⇒ 丢掉占位；`BuildTimeSeconds == 0` 或工期到期 ⇒ `CompleteConstruction`（补 footprint + Ether 标记、删建造 fragment、`Record.bComplete = true`）；
- 占位**不在这里**释放（等 footprint 观察者，见 §3.2 说明）。

### 4.5 运行期增删（服务器权威）

```cpp
// UAsceBuildingSubsystem
bool PlaceBuilding(const FAsceBuildingPlacement& Placement, FString* OutError);   // 建"建造中实体"+占位
bool DemolishBuilding(FMassEntityHandle Building, FString* OutError);             // 建造中=取消；已完工=销毁（观察者复原）
```
- `PlaceBuilding`：校验 → 建建造中实体 + 占位 → 施工阶段完工后才真正生效（costfield/视野/Ether 随之）。
- `DemolishBuilding`：建造中的工地直接取消（销毁实体 + 清占位，没有 footprint ⇒ 无副作用）；已完工的销毁实体（Ether `RemoveNode`、costfield/视野/建筑层由观察者复原）。
- 客户端请求：先在本地做一遍校验（立即反馈），再发 RPC；**服务器重做校验**（唯一真相）。
- **搬家 = `DemolishBuilding` + `PlaceBuilding`**（不提供"原地改 footprint"的接口，避免增量漏项）。

### 4.6 引导顺序（世界初始化）
```
AAsceWorldMapReplicatorActor::BeginPlay
  ├─ SpatialGrid->ConstructGrid(...)                 // 单位层
  ├─ SpatialGrid->ConstructBuildingsGrid(WorldEnd/100, 100, 4)   // ★ 本次新增：建筑层
  ├─ Fog->InitializeVisionMap(...)
  └─ (地图/流场/Bake 数据就绪)
调度器 Tick
  ├─ 阶段 0：UAsceBuildingSubsystem::RunBootstrapStage()   // ★ 本次新增：预摆建筑落地
  ├─ 阶段 1：流场/寻路
  ├─ 阶段 2：空间数据（建筑层收录本帧新建筑）
  ├─ 阶段 3：移动
  ├─ 阶段 4：视野/雾
  ├─ 阶段 5：Ether drain → 模拟
  └─ 阶段 6：雾渲染上传
```

## 5. 校验规则（不许重叠）

权威端在**创建 entity 前**校验（`ValidatePlacement`）：

1. **定义有效**：`BuildingDefId` 非空且是"1..65535 的数字行名"，能在实体定义表里查到建筑定义 `FAsceBuildingDefBase`（`UAsceEntityDefLibrary`；Ether 建筑是其子类 `FAsceEtherBuildingDef`）；`SizeX/SizeY` 由 `GetOccupiedBounds` clamp 到 ≥1；
2. **越界**：旋转后的最终 AABB 必须全部落在地图范围内（`FWorldMapData` 的 `GetGridCountX/Y`）；
3. **目标格必须"纯可通行"**：最终 AABB 逐格查 `FWorldMapData::IsCellCleanPassable(x,y)`（cost == `AsceCostField::PlainPassableCost` = 1）—— 这一条同时挡住
   - 地形墙 / 地形代价（bake 写 `BlockedCost`/其它 cost）；
   - **已建成建筑**（建筑 footprint 的 Add 观察者写 `BlockedCost`）⇒ 所以不需要再查"建筑层重叠"；
4. **不与"建造中"的工地重叠**：遍历 `PendingBuilds`，读 `FAsceConstructingFragment` 的未旋转占位 → 换算最终 AABB → AABB 判交 ⇒ 有交即拒绝（建造中的工地还没写 costfield，靠这条兜）；
5. （后续）资源/前置/成本、建造时间/材料（已在 `FAsceBuildingDefBase::BuildTimeSeconds` 留字段）。

非权威端放置时用**同一套** `ValidatePlacement`（纯查询、无副作用）提前校验，服务器端再校验一次（防作弊）。
> ⚠️ 依赖的不变式：**建筑 footprint ⇒ costfield 落 `BlockedCost`，拆除 ⇒ 复原**（由 costfield 的 Add/Remove 观察者保证，放置校验保证只建在 `cost==1` 的格上 ⇒ Remove 复位成 1 是正确的）。

## 7. 实施步骤（每步一个编译点）

1. ✅ **建筑层就绪条件 + 构建**：`IsBuildingsGridReady()`；`AAsceWorldMapReplicatorActor` 补 `ConstructBuildingsGrid`（逻辑格 = 流场格 100cm，粗格 4）。
2. ✅ **摆放 Actor**：`AAsceBuildingPlacementActor`（字段 + 编辑器占格标记 + 吸附 + BeginPlay 注册）。
3. ✅ **子系统 + 引导阶段**：`UAsceBuildingSubsystem`（Pending / `ValidatePlacement` / 创建实体 / 销毁 Actor / 日志），调度器接阶段 0。
4. ✅ **建造流程（建造中 fragment → 施工阶段完工 → 观察者）**：`FAsceConstructingFragment` + `RunConstructionStage`（阶段 0b）+ `AsceBuildingFootprintObserverProcessor` 释放占位；`ValidatePlacement` 改成"纯可通行 + 不与建造中工地重叠"（不再查建筑层）。
5. ⏳ **运行期增删**：待接客户端请求 RPC + 用调试器验证一次"建造 → 完工 → 拆除"全链。
6. ⏳ **收尾**：`AAsceEtherDebugger` 的摆放路径改为复用 `UAsceBuildingSubsystem`（避免两套），调试器只留可视化。
7. ⏳ **后续**：costfield 分层（BaseLand / Building / Special + 只在最终阻挡变化时写/复制/触发地图处理）；建筑层 `bBuildingsDirty` 门控整层重建；建造材料/成本。

## 8. 未决 / 后续

- **视野遮挡高度的基准**（贴地带来的新问题）：建筑现在有基座 Z（贴地），而 vision 侧的高度语义目前隐含"地面 = Z=0" ⇒ 坡上建筑的遮挡会差一个 `BaseZ`。需要定：**相对基座**（vision 消费侧加上建筑实体 Z）还是**绝对高度**（写 footprint 时就把 `BaseZ` 折进 `OcclusionHeightCm`）。
- **贴地的"排除标记"**：`UAsceTerrainHeightProcessor` 的查询只要 `FTransformFragment` ⇒ 现在**所有**带 Transform 的实体都会被贴地；以后如果有"不该贴地"的实体（飞行单位 / 空中投射物 / 悬空件），需要加一个标记 tag（例如由地面单位/建筑 trait 添加的 `FAsceTerrainSnapTag`）来排除（`AsceTerrainHeightProcessor.cpp` 里已留 TODO）。
- **实体表现**：统一做（Mass 表现层 / 复制 → 渲染），本次不碰；因此客户端也销毁摆放 Actor。
- **存档**：统一做；本设计保证"地图预摆 = 摆放 Actor（可序列化）+ 运行期增删 = 服务器事件"，都能重放出建筑集合。
- **建造菜单目录**：哪些建筑 def 行（`FAsceBuildingDefBase` 子类）可造 + 成本/前置/分类 —— 一张表走 `DataTableSystem`，UI 层另做。
- **批量摆放工具**：多选/框选摆放、复制粘贴、对齐吸附（先一个建筑一个 Actor，工具后做）。
- **`FAsceTeamFragment` 归属**：建筑阵营字段现在只落到实体上，具体玩法消费（占领/攻击）后续定。
- **旋转可视化**：摆放 Actor 在编辑器里应按 `Rotation` 画旋转后的占位框（实现时一起做）。
