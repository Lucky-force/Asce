# 代价分层设计（BaseLand / Building / Special）

> 代码：`AsceMass/FlowField/AsceLayeredCostField.h/.cpp`（数据 + 组合），挂在 `AAsceWorldMapReplicatorActor::LayeredCostField` 上，
> 对外入口 `UAscePathFindingSubsystem::GetLayeredCostFieldMutableForAuthority()` / `AddSpecialCostOp` / `RemoveSpecialCostOp`。

## 1. 为什么要分层

`FWorldMapData::CostFields` 是**最终结果**，谁都能直接写 ⇒ 来源互相覆盖，且"墙"在数据上不区分来源。两个具体问题：

1. **拆除抹地形**：建筑压在带地形代价/地形墙的格上时，旧 Remove 观察者硬写 `1`，把地形一起抹成"可通行"；
2. 无法表达"临时强制阻挡/强制可通行"这类技能效果（填海/搭桥），且任何一方直写都会打断别人的数据。

分层后：最终值 = 三个来源层**组合**的结果，并且**只在组合结果真变时**才写 `CostFields`（⇒ 才会复制、才会标脏扇区/重建墙簇）。

## 2. 三层数据

| 层 | 字段 | 内存 | 语义 | 谁写 |
|---|---|---|---|---|
| BaseLand | `TArray<uint8> BaseLandCost` | 1 B/格（dense） | 地形基线，**完整 cost 值**（含 bit7 墙位、低 7 位地形代价预留位）。bake 应用完抓一次**快照**（未烘焙地图 = 抓当时的初始值） | `AAsceWorldMapReplicatorActor::InitializeMapDimensions`（authority） |
| Building | `TArray<uint8> BuildingCost` | 1 B/格（dense） | `0` = 无建筑；`AsceCostField::BlockedCost`(255) = 建筑占用。建筑不重叠 ⇒ **单值、不叠加** | `AsceCostFieldFootprintObserverProcessor` 的 Add/Remove |
| Special | `TBitArray<> SpecialContributionBitMap` + `TMap<uint32, FAsceSpecialCostCell> SpecialContributions` | 1 bit/格 + 稀疏条目 | 技能/机制施加的临时影响。**只存 Op 不存代价**（代价已确认只影响寻路、而寻路只管 block）：`Block` = 强制阻挡；`Unblock` = 强制可通行（**只清地形，不清建筑**）。每格 `TArray<FAsceCostOp>` 按 ID 升序（二分插入/删除/查找） | `UAscePathFindingSubsystem::AddSpecialCostOp` / `RemoveSpecialCostOp` |

- 三层都**只在服务端权威端**维护、**不复制**；客户端只用复制下来的最终 `CostFields`。
- Special 选型的目的是**访问开销**而不是内存：
  - `SpecialContributionBitMap` 是 dense 位图，作为"这格有没有 special"的 O(1) 短路 —— 绝大多数格没有 special，一次位测试即返回，**完全不碰 TMap**；
  - 只有真的有 special 的格才付一次 `TMap.Find`，再遍历那个几元素的小数组。
- 不变式：`SpecialContributions` 有 key 的格 ⇔ bitmap 置位（最后一个贡献移除时同步清位 + 删条目）。

## 3. 组合规则

```
FinalBlocked = BuildingBlocked || AnyBlock || (BaseBlocked && !AnyUnblock)
```

代码：`FAsceLayeredCostField::ComposeCellCost(GridIndex)`（O(1)：建筑阻挡 → special 位图短路 → base）。

- **Block 优先于 Unblock**（同格同时存在 ⇒ 阻挡）；
- **Unblock 只清地形**：建筑阻挡**永远**不能被 special 清除（建筑是实体占位，清掉会和"实体仍占着这格"矛盾）；
- special 命中值为 `AsceCostField::PlainPassableCost`(=1)；越界按阻挡（与 `FWorldMapData::IsCellBlocked` 一致）。

## 4. 写入路径（真变才写）

- 层写入函数（`SetBaseCost` / `SetBuildingCost` / `AddSpecialOp` / `RemoveSpecialOp`）**只改层**，不碰 `CostFields`；
- `FlushCell(GridIndex, WorldMapData)` / `FlushAll(WorldMapData)` 组合并与 `CostFields` **现值比较，不同才** `SetCostField`；
- ⇒ 幂等：对已经是墙的格再加 `Block`、两个建筑层写同一个值，都**不会**重复触发 `PendingUpdateCostFields`/扇区脏标记/墙簇重建；
- `UAscePathFindingSubsystem::AddSpecialCostOp/RemoveSpecialCostOp` = 改 Special 层 + `FlushCell`（单格）。

## 5. Handle 契约

```cpp
// (GridIndex << 32) | ID  ⇒ 由 Handle 直接反推格子，不需要任何反查表
Handle = ((uint64)GridIndex << 32) | (uint64)ID
```

- **同一格上同一 ID 只对应一种 Op**（否则 Handle 无法唯一定位）；
- `ID` 建议由使用方**全局单调递增**、在一次贡献的生命周期内唯一；铺多格时复用同一个 ID（每格一个 Handle，靠 GridIndex 区分）。
  否则"陈旧 Handle 误删后来复用同一 ID 的新贡献"是可能的；
- 陈旧/重复释放：找不到条目时打 Warning 并忽略（不崩、不动 bitmap）；越界 Add 返回 `FAsceLayeredCostField::InvalidHandle`。

## 6. 生命周期与基线刷新

- **抓快照时机**：`InitializeMapDimensions()` 里、bake 应用之后（authority）：逐格 `SetBaseCost(现值)` → `FlushAll()` 并 `ensureMsgf(!bChanged)` —— 因为 base = 现值、Building 全 0、Special 为空，组合结果必然等于现值，`FlushAll` **必须**是空操作（这是"接线等价"的自查）。
- 该函数由 `UAsceSimulationSubsystem::TryRunWorldInit()` 单次调用（`bWorldInitialized` 门控）⇒ 目前不存在二次初始化。
- 若将来支持**运行时重新 bake / 换图**：必须按序 `重建 WorldMapData → 重新抓 BaseLand 快照 → FlushAll`，且 Building/Special 层要视为失效（`InitLayeredCostField` 会整层 Reset）。
- 客户端：`FWorldMapData::PostReplicatedChange` 之后照旧由现有逻辑重建墙簇；读到的就是组合后的最终值。

## 7. 与其他系统的边界

| 系统 | 关系 |
|---|---|
| 建筑放置校验（`UAsceBuildingSubsystem::ValidatePlacement`） | 读 `IsCellBlocked` / `IsCellCleanPassable`，即**组合后的最终值** ⇒ Special `Unblock` 出来的"可通行"格也能建、Special `Block` 的格不能建（符合预期） |
| Ether / 视野 / SpatialGrid / 寻路 | 都读最终 `CostFields`，**不需要感知分层** |
| `AAsceFlowFieldDebugger` | 地形写入（占位全 1 / 测试墙 / F·E 刷擦墙）改走 **BaseLand 层**（等同"手工改地形"），否则未烘焙地图上 base 与现值会不一致、建筑拆除会还原成初值 0 |
| 数据表的 `RefreshData` | 与代价分层无关 |

## 8. 实施步骤（已完成，每步一个编译点）

1. ✅ **结构**：`FAsceLayeredCostField`（三层 + 组合 + Flush + Special Handle），挂 `AAsceWorldMapReplicatorActor`，`UAscePathFindingSubsystem` 转发 authority 访问器（不接线）。
2. ✅ **BaseLand 接线**：bake 后抓快照 + 全量 `FlushAll` 自查等价（断言"必须是空操作"）。
3. ✅ **Building 接线**：`AsceCostFieldFootprintObserverProcessor` 的 Add/Remove 改写建筑层 + `FlushCell` ⇒ 修掉"拆除抹地形"；顺带把调试器的地形写入改走 base 层。
4. ✅ **Special 层**：`UAscePathFindingSubsystem::AddSpecialCostOp/RemoveSpecialCostOp` + 调试命令（见 §9）。

## 9. 调试（选中 `AAsceFlowFieldDebugger` 后在控制台敲，坐标是世界坐标）

```
FlowFieldDebugAddSpecial  WorldX WorldY Op ID   // Op: 0=Block 强制阻挡, 1=Unblock 强制可通行(只清地形)
FlowFieldDebugRemoveSpecial ID
FlowFieldDebugDumpCell    WorldX WorldY         // 打印 base / building / hasSpecial / composed / costField / special 条目数
```

自测点：`composed == costField`；对地形墙加 `Unblock` ⇒ 变可通行；对建筑占用的格加 `Unblock` ⇒ 仍阻挡；对已是墙的格加 `Block` ⇒ `FlushCell` 空转。

## 10. 未决 / 注意

- **地形代价（低 7 位）目前是预留语义**：寻路只管 block；放置校验要求组合值 == 1，所以"带地形代价但可通行"的格暂时不能建 —— 将来放宽只需改校验规则。
- **Special 的 ID 分配策略**由使用方（技能/机制）负责，建议"一次逻辑贡献 = 一个全局单调 ID"。
- 运行时热重载地图/bake 未支持（见 §6）。
