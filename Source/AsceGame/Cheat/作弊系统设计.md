# 作弊系统设计（`Source/AsceGame/Cheat/`，独立功能）

> 状态：**基础层 + RTS 组件已落地**；挂载走 **GameFeatureAction_AddComponents**（不写死进 PlayerState）。
> 目标：**加一个新作弊 = 只写一个 UCLASS**；控制台和 UI **都能枚举/执行**；**零侵入**其它玩法代码；
> **按模式隔离**（各模式一个作弊组件 + 一个函数库），**不写死进 PlayerState / 各模式**。
>
> 另见：`Combat/技能编辑器设计.md`（技能运行时，与本系统无依赖）。

## 1. 为什么不用 `UCheatManager`

它的 `Exec` 是"编译期固定 + 按位置强类型解析"，既不能 `Key=Value` 可选参数，也不能被 UI 枚举
（且 Shipping 里 `UE_WITH_CHEAT_MANAGER=0`，`AddCheats` 整段被注释掉）。我们用 `IConsoleManager`
（`FAutoConsoleCommandWithWorldAndArgs`）+ 自己的动作注册表。

## 2. 目录与分工

```
Source/AsceGame/Cheat/                        ← 与 GameFeature 无关的基础层
├── AsceCheatDefines.h                        编译开关 ASCE_CHEAT_ENABLED（默认全构建都编）
├── AsceCheatTypes.h/.cpp                     通用参数类型（Float/Int/Bool/Name/Entity/Vector）+ 参数/上下文
├── AsceCheatAction.h                         动作基类（数据 + Execute）
├── AsceCheatLibrary.h/.cpp                   通用能力库（发现 / 解析 / 校验 / 执行 + 授权 / 开关控制台）—— 不判权限
├── AsceCheatConsole.cpp                      控制台：asce.cheat / asce.list / asce.grant / asce.console
├── Console/
│   └── AsceCheatConsoleWidget.h/.cpp         Slate 控制台（输入 / 历史 / 输出；Shipping 也能用）
├── Components/
│   ├── AsceCheatComponentBase.h/.cpp         所有模式共用的组件基类（权限 + RPC + 输出 sink + 控制台开关）
│   └── AsceRTSCheatComponent.h/.cpp          RTS 模式的组件（只给"动作基类 + 本模式函数库"）
└── Actions/
    └── RTS/                                  ← 各模式独占目录，之后别的模式并列
        ├── AsceRTSCheatAction.h              RTS 动作基类（用于按模式过滤）
        ├── AsceRTSCheatArgTypes.h/.cpp       RTS 专用参数类型（DefRow / ActionRow / Team）
        └── AsceRTSCheatLibrary.h/.cpp        RTS 函数库入口（后续 RTS 复合操作也放这）
        ├── AsceRTSCheatOps.h/.cpp            RTS 具体实现（生成队列 / 先校验再放置 / 拆除 / def 列表）
        └── AsceRTSCheatActions.h/.cpp        第一批动作（SpawnUnits / PlaceBuilding / DestroyEntity / ListDefs）
```

**为什么不是 Subsystem**：作弊"能力"是**函数**（发现/解析/执行），不需要生命周期管理；
按模式拆分时，Subsystem 反而要处理"哪个模式创建哪个实例"。改成**静态函数库**后：
各模式的组件调**自己模式的库**，库之间只共享基础层。

## 3. 数据结构

- **`FAsceCheatArgType`（`FInstancedStruct`，多态）**：类型**自己**负责 `Validate` / `GetSuggestions(World)`（UI 下拉）/
  `AsFloat|AsInt|AsBool|AsName|AsEntity|AsVector`。加一种参数 = 加一个 USTRUCT。
  - 基础层：`Float / Int / Bool / Name / Entity / Vector`
  - RTS（`Actions/RTS/AsceRTSCheatArgTypes.h`）：`DefRow / ActionRow / Team`
- **`FAsceCheatActionArg`**：`{ ArgName, ArgContent(唯一真相), ArgType, DisplayName, Tooltip, bRequired }` + `GetFloat()` 等 C++ 读法。
- **动作参数一律 `Key=Value`**（`TMap` 无序，**不支持位置参数**）；没给的用 `BuildArgs()` 里的默认值。

## 4. 执行流程

```
asce.cheat / UI
  → 找本机玩家的 UAsceCheatComponentBase
  → RequestLine(Line)
      ├─ 权威端（主机/单机）：直接 ExecuteLine
      └─ 客户端：Server_RunCheatLine(Line)
            → 服务端校验 bCheatAllowed → ExecuteLine
            → Client_CheatResult(Line, Summary, Error)   // 回显到**发起者**控制台
  → ExecuteLine（各模式组件覆写）→ 本模式函数库 → UAsceCheatLibrary::RunFromLine
      → 动作默认值 → 输入覆盖 → ArgType->Validate → Action->Execute(Context)
```

约定：**生成单位走生成队列**（不当帧拿 handle）；**建筑违规永不允许强制放置**；生成允许选 `TeamId`。

## 5. 两层开关

- 编译期：`ASCE_CHEAT_ENABLED`（默认 1 = 全构建都编，**含 Shipping；发行包也保留作弊指令**；只想剔除时在 `Build.cs` 里 `=0`；`Run`/`IsCheatAvailable`/Server RPC 都做这个硬 gate）；
- 运行时**唯一鉴权**：组件上的 `bCheatAllowed`（per-player、服务端权威、复制给属主）；
- cvar **`Asce.Cheat.Enable`**：**只用于主机/单机启动时给自己授权**（`BeginPlay` 里 `SetCheatAllowed(true)`；Shipping 默认 0）。客户端本机 cvar 不参与授权；客户端权限只由主机 `asce.grant` 设置，运行时改权限也用 `asce.grant`。
- **发行包**：指令保留；主机/单机即使 `bCheatAllowed=false` 也允许打开 Slate 控制台（用于 `asce.grant` 自授权），授权后正常执行；客户端仍需主机 grant。

## 6. 权限模型（per-player）

- **判定**（`UAsceCheatComponentBase::IsCheatAvailable`）：`IsCheatSupported() && bCheatAllowed`（不再看 cvar）；
- **主机/单机**：`BeginPlay` 读 cvar，开启则给自己 `bCheatAllowed=true`；cvar 关闭时可在控制台用 `asce.grant <自己> 1` 开；
- **客户端**：`bCheatAllowed` 只能由主机 `asce.grant` 设置（复制给属主），本机 cvar 无效；
- **服务端校验**（`Server_RunCheatLine`）：`bCheatAllowed` 才执行（加编译期硬 gate）；
- **授权**：控制台 `asce.grant <索引|玩家名> [0|1]`（默认 1=开）→ `SetCheatAllowed`；只有服务端能改；
- 属主 UI 用 `IsCheatAvailable()` 决定是否显示面板。

### 6.1 组件怎么挂：GameFeature，不写死

- 用**引擎自带**的 **`UGameFeatureAction_AddComponents`**
  （`Engine/Plugins/Runtime/GameFeatures/Source/GameFeatures/Public/GameFeatureAction_AddComponents.h`，**不要再自己写一份**：
  UHT 不允许两个同名头文件）：
  ```ini
  ComponentList:
    ActorClass      = AModularPlayerState   # 不是 AAscePlayerState，避免依赖具体模式
    ComponentClass  = UAsceRTSCheatComponent
    bServerComponent = true                 # 服务端创建（复制组件必须只服务端建）
    bClientComponent = false
    AdditionFlags   = AddUnique
  ```
- **引擎事实**（`ModularGameplay/Private/Components/GameFrameworkComponentManager.cpp`）：
  - `CreateComponentOnInstance`（:482）对**复制组件只在权威端创建**，其余端靠普通子对象复制；
  - 组件名用**类名**（:510）⇒ 两端同名 ⇒ **Server/Client RPC 双向可用**；
  - 非复制组件才是"两端各自创建"。
- ⇒ 组件挂在 `AModularPlayerState` 上，只有**该模式的 GameFeature 激活时**才出现：
  RTS 模式玩的时候自动在 PlayerState 上创建 `UAsceRTSCheatComponent`，别的模式可以另写自己的。

## 7. 命令入口

- 开发/PIE：真控制台 `asce.cheat` / `asce.list` / `asce.grant` / `asce.console`；
- 权威端没有本机玩家（专用服务器控制台）：`asce.cheat` 会退化为"用任意一个玩家的组件执行"；
| Slate 控制台（`SAsceCheatConsole`） | ✅ 已写（`Cheat/Console/`，`asce.console` 开关） |
| GameFeature 里加「打开控制台」的按键绑定 | ⏳ 在编辑器里加 |
  （`~`/`CheatManager`/`-ExecCmds` 都不可靠：`UnrealEngine.cpp:2239` 在 `#if !UE_BUILD_SHIPPING` 里，
  但 `IConsoleManager` 命令与 `PC->ConsoleCommand(Line)` 仍在）：
  - `asce.*` 由作弊组件处理（主机直接跑，客户端转 Server RPC，**结果回包也进面板**）；
  - 其它行交给 `PC->ConsoleCommand(Line)`（cvar / stat / 引擎命令照常可用）；
  - `↑`/`↓` 历史、`Esc` 关闭；打开时 `SetIgnoreMoveInput/LookInput(true)`，关闭恢复 `GameAndUI`；
  - 动作名可以**直接输**（等价 `asce.cheat <Action> …`）；
  - **动态补全**：输入框上方半透明提示按当前输入给"下一个填什么"（命令 → 动作 → 参数名 → 候选值），
    已填参数打 `✓`、必填未填标 `*`；`Tab` 唯一候选直接补、多个先补公共前缀并在输出区列出。
- **开关键**：`UAsceCheatComponentBase::ToggleConsole()` / `UAsceCheatLibrary::ToggleConsoleForLocalPlayer(WorldContext)`
  —— 按键绑定**放在 GameFeature 的输入**里，绑到一个调用它们的函数即可；开发期也可以直接 `asce.console`。
  主机/单机即使尚未授权也允许打开（用于 `asce.grant`）；客户端仍需 `bCheatAllowed`。
